# GuessWho 前端實作與美術規範

本文件是 `apps/web` 的強制前端規範，集中管理技術選擇、責任邊界、頁面結構、響應式版面、觸控行為、無障礙、圖片處理與 Retro Design。架構、Server 權限與遊戲規則以 [`agent.md`](./agent.md) 為準；如果兩份文件衝突，遊戲結果與資料權限以 `agent.md` 為準，畫面呈現與前端互動以本文件為準。

## 前端技術與責任邊界

- 使用 Next.js App Router、React、TypeScript 與 Tailwind CSS。
- 使用 Firebase Web SDK 完成匿名登入、取得 ID Token 與 Storage 圖片上傳。
- 使用 `socket.io-client` 連接獨立 Game Server。
- Game Server 傳回的 `room:state` 是畫面狀態的唯一依據；React state 只保存彈窗開關、目前聚焦卡片、尚未送出的表單與圖片裁切預覽等暫時 UI 狀態。
- 前端只送出玩家意圖，不自行決定先手、回合切換、勝負、房主、ready、target 或 `foldedCardIds`。
- 前端不得直接寫入 Firestore 遊戲資料，也不得取得對手秘密目標或房間密碼。
- 所有操作都要等待 Socket acknowledgment；成功後以 Server 最新 `room:state` 更新畫面，不做會改變規則結果的樂觀更新。

前端公開環境變數：

```text
NEXT_PUBLIC_FIREBASE_*
NEXT_PUBLIC_GAME_SERVER_URL
```

Firebase Web Config 是公開設定，不是 Firebase Admin 憑證。不得把 Service Account JSON、私鑰或 Game Server 的秘密放進 `NEXT_PUBLIC_*`。

## 前端先行與人工驗收

- 開發順序與必須暫停的人工驗收點，以 `agent.md` 的「開發順序」為準。
- 人工驗收前使用明確標示的展示模式，可用符合 shared 型別的本地 mock 狀態模擬房間、回合、蓋牌及操作成功／失敗，讓完整前端可獨立操作。這是上述 Server 狀態規則在展示階段的限定例外，不能作為正式遊戲裁判。
- 展示模式不需要 Firebase 憑證或正在執行的 Game Server，不寫入真實 Firestore 或 Storage；圖片選檔與裁切先使用本地預覽。
- 使用簡單的資料入口隔離 mock 與真實連線，讓頁面與元件共用同一組資料型別；不要在每個元件散落 mock 判斷。
- 前端完成後交付人工驗收並停止。使用者明確確認後才接上真實 Firebase／Socket.IO；正式環境不得啟用展示控制或在連線失敗時自動退回 mock。

## 設計方向

整體採用 1960～1980 年代印刷品與桌遊盒風格，呈現溫暖、略微褪色的類比質感。畫面應像一盒保存良好的復古猜人桌遊，而不是現代 SaaS 後台。

避免科技霓虹、純白背景、玻璃擬態、柔和漂浮陰影與過度現代的幾何無襯線風格。

## 設計 Token

在 `globals.css` 定義 CSS variables，Tailwind class 優先引用這些 token：

```css
:root {
  --paper: #f4e8d1;
  --card: #fff3e0;
  --ink: #3e2723;
  --orange: #d35400;
  --mustard: #f1c40f;
  --sage: #7a8b5a;
  --shadow: #795548;
  --danger: #a63d2f;
}
```

- 頁面背景使用 aged-paper 米白色，不用純白。
- 主要文字使用深棕色，確保閱讀對比。
- 主要操作使用焦橙色，提示與焦點可使用芥末黃。
- 鼠尾草綠用於完成、在線與安全狀態。
- 錯誤、等待、成功不能只靠顏色區別，必須有文字或圖示。

## 字體

- 遊戲 Logo 與大標題使用 Cooper Black 類型的粗圓復古字體。
- 正文使用 Georgia 或 Garamond 類型的 serif 字體。
- 房號、密碼、回合與狀態標籤可使用 Courier 類型的 monospace 字體。
- 有合法字型檔時使用 `next/font/local`；不要從不明來源下載字型。
- 字型載入失敗時仍須有可讀的 serif fallback。

## 元件造型

- 卡片使用 `2px` 深棕外框、約 `12px` 圓角及無模糊的實色偏移陰影。
- 偏移陰影以 `8px 8px 0 var(--shadow)` 為基準；手機卡片可縮小至 `3px 3px`，不使用柔和霧化陰影。
- 按鈕、房號與玩家狀態可使用復古貼紙、票券、印章或徽章造型。
- 波浪邊框、半色調與輕微旋轉標籤只作點綴，不能妨礙辨識或點擊。
- 角色照片是卡片主角，裝飾不得蓋住姓名、狀態或操作按鈕。
- 選中、蓋牌、秘密角色與不可操作狀態必須有不同的形狀、文字或圖示提示。

## 紙張與印刷質感

- 全站最多使用一層低透明度 grain／noise，不在每張卡片重複載入材質圖。
- 優先使用 `body::before` 與本地小型材質圖，並設定 `pointer-events: none`。
- 可使用輕微的半色調、印刷錯位及硬式文字陰影，但不可降低文字清晰度。
- 紋理需在低階手機保持流暢；若造成卡頓，先移除紋理，不加入效能套件。

## 響應式設計原則

採用 mobile-first，優先完成手機直向與平板直向，再擴充平板橫向與桌機。不得只縮小桌機版。

### Breakpoint 與安全區域

- 手機：`320px～639px`。
- 平板：`640px～1023px`，直向與橫向都要驗證。
- 桌機：`1024px` 以上。
- 使用 `100dvh`，不要只使用在手機網址列伸縮時容易跳動的 `100vh`。
- 頂部狀態列與底部操作列必須加入 `env(safe-area-inset-top)`、`env(safe-area-inset-bottom)`，不能被瀏海、動態島或系統手勢區遮住。
- 方向或視窗大小改變時以 CSS 重新排版，不靠重新整理頁面。
- 不允許水平捲動；大廳與圖片編輯畫面可以垂直捲動，正式遊戲畫面則固定在一個視窗內。

### 各裝置版面

- 手機：上方使用緊湊狀態列，中間是正方形卡片區，常用回合操作放在底部；不使用永久左右側欄。
- 平板：正方形卡片區仍是主體。直向沿用手機結構但增加間距；橫向可把玩家與回合資訊放在窄側欄，不能壓縮卡片區成長方形。
- 桌機：卡片區置中，狀態或說明可放兩側；卡片區最大尺寸需受視窗高度限制，不能超出首屏。

## 中央正方形卡片區

舊版 `#cards-container` 以固定網格置中；新版保留這個核心概念，但改為所有裝置都能完整容納的正方形遊戲區。

- 卡片區永遠保持 `aspect-ratio: 1 / 1` 並水平置中。
- `9`、`16`、`25` 張卡片固定使用 `3×3`、`4×4`、`5×5`。不得在手機改成 `2` 欄或長條捲動，所有卡片必須同時出現在中央正方形內。
- 卡片一律依數字 `cardId` 升冪，由左至右、由上至下排列。載入速度、Firebase 回傳順序、斷線重連或雙方裝置尺寸都不能改變順序。
- `25 → 9` 時畫面只保留 `cardId` 為 `1～9` 的前九張，排列位置不重洗。
- 卡片區尺寸同時受可用寬度與可用高度限制，可使用下列概念；實作時將頂部與底部實際保留高度做成 CSS variable：

```css
.game-board {
  --board-gap: clamp(3px, 1vw, 12px);
  inline-size: min(
    calc(100dvw - 24px),
    calc(100dvh - var(--top-ui-height) - var(--bottom-ui-height) - 24px),
    760px
  );
  aspect-ratio: 1 / 1;
  display: grid;
  gap: var(--board-gap);
}
```

- 以卡片數量設定完整 class：`grid-cols-3`、`grid-cols-4` 或 `grid-cols-5`，不得動態拼接 Tailwind class 名稱。
- 每格使用 `minmax(0, 1fr)`；卡片本身 `aspect-square min-w-0 min-h-0 overflow-hidden`，不能由圖片原始尺寸撐大。
- 圖片固定填滿卡片，使用 `object-fit: cover` 與置中裁切。卡片不提供拖曳改尺寸、手勢縮放或自由移動。
- 姓名標籤固定在圖片底部。`5×5` 的窄手機版可縮短過長姓名並以省略號顯示；完整名稱要能在放大視窗與替代文字中取得。
- 蓋牌後仍保留原本格位與卡片編號，不可把卡片從 grid 移除而造成其他卡片位移。

## 卡片點擊、放大與操作

卡片本體只負責開啟細節，不在小縮圖上塞入蓋牌、指認或編輯按鈕。

### 放大視窗

- 點擊或鍵盤啟用卡片後，開啟 `position: fixed; inset: 0` 的 modal，背景使用深色半透明遮罩。
- 被選卡片的正方形圖片置中放大，手機建議最大為 `min(84dvw, 56dvh)`，平板與桌機最大為 `min(64dvw, 68dvh, 640px)`。
- 圖片維持固定正方形與 `object-fit: cover`；不得依手指拖曳、雙擊或捏合改變大小和位置。
- 圖片下方顯示卡片編號與完整名稱，再顯示合法操作列。底部操作列要保留安全區域，不能遮到圖片或系統手勢區。
- 點擊遮罩、右上角關閉鈕或按 `Escape` 可關閉。關閉後焦點回到原卡片。
- Modal 必須有 `role="dialog"`、可讀標題、focus trap 與背景不可聚焦處理。

### 不同狀態的底部操作

| 房間狀態與條件 | 放大圖片下方顯示 |
|---|---|
| `lobby` 兩位玩家 | 「設為秘密目標」，並可修改名稱、替換圖片 |
| `lobby` 房主 | 除了共同的卡片操作，另可調整卡片數量 |
| `playing`、未蓋牌 | 「蓋牌」；只有目前回合玩家另外顯示「指認」 |
| `playing`、已蓋牌 | 「翻回」；指認仍須依目前回合權限決定是否顯示 |
| `paused` | 只顯示斷線倒數與「等待玩家重連」，所有操作停用 |

- 「蓋牌／翻回」只送出 `card:fold-toggle`；收到 Server 成功狀態後才改變卡面。
- 「指認」即 `game:guess`。第一次點擊先開確認畫面，再次明確確認才送出，確認內容必須顯示圖片與完整姓名。
- 完成提問或猜錯時，Server 都會自動切換玩家；前端不顯示額外的回合確認操作。
- Disabled 操作要顯示原因，例如「現在不是你的回合」，不能只把按鈕變灰。

## 觸控、縮放與拖曳限制

正式遊戲畫面必須保持固定，不因誤觸雙擊、圖片拖曳或手勢而改變卡片大小。

- `playing` 與 `paused` 的整個遊戲 viewport 使用 `height: 100dvh`、`overflow: hidden`、`overscroll-behavior: none` 與 `touch-action: none`；中央遊戲區與放大圖片同樣維持 `touch-action: none`。
- 按鈕、連結與大廳表單使用 `touch-action: manipulation`，避免雙擊被解讀為頁面縮放並保留正常點擊。
- 所有角色 `<img>` 設定 `draggable={false}`、`user-select: none`、`-webkit-user-drag: none` 與 `-webkit-touch-callout: none`。
- 僅在遊戲區與圖片上攔截 `dragstart`；不得在 `window` 全域攔截所有 pointer 或 touch 事件，以免破壞表單與大廳垂直捲動。
- 不實作圖片 pinch-to-zoom、拖曳平移、雙擊放大或可變 scale；放大尺寸只由上述 modal 的 CSS 規格決定。
- 不在 Next.js viewport metadata 設定 `user-scalable=no` 或 `maximum-scale=1`。正式遊戲 route 內禁止雙擊、拖曳或捏合造成縮放，但仍保留使用者透過瀏覽器選單或作業系統輔助功能放大文字與頁面的能力。

## 各頁面規則

### 首頁

- 清楚分成「創建房間」與「加入房間」兩個入口。
- 創建區要能選擇 `9／16／25` 張卡片與房間保存方式。
- 加入區先要求房號；保留房間再顯示密碼欄位。
- UI 必須提醒保留房間的密碼只是房間通關密碼，不要使用個人帳號常用密碼。
- 遊戲規則使用可閱讀的桌遊說明書排版，不把整頁塞滿裝飾。

### 房間大廳

- 清楚顯示房號、房主、兩位玩家、卡片數量、連線及準備狀態。
- 房主設定區使用獨立控制面板；來賓不顯示沒有權限的編輯控制。
- 修改卡片數量採「選擇草稿 → 確認變更」；點擊 9／16／25 不立即修改卡組。確認前列出會移除的編號或新增空位，取消、關閉與 Escape 都放棄草稿；操作失敗則保留草稿供重試。
- 卡片一律依 `cardId` 數字升冪排列。
- 大廳不開放蓋牌；點卡片只能選目標，房主另可進入名稱與圖片編輯。
- 卡片未完成、目標未選、玩家未準備時，直接說明無法開始的原因。
- 房主的開始按鈕是大廳唯一主要操作；條件未滿足時顯示禁用原因。
- 房主不顯示「準備／取消準備」；房主選好秘密目標後直接使用「開始遊戲」。非房主顯示「準備／取消準備」，並提示等待房主開始。
- 開始條件為兩位玩家在線、卡組完整、雙方目標有效且非房主已準備；不得要求房主 ready。房主移交後按目前身分更新操作按鈕。
- 非房主已準備且目標有效時，停用「設為秘密目標」並提示先取消準備；目標因卡組縮減被清除時，允許直接補選且保留 ready。
- 房主修改卡片後，ready 與仍有效的 target 在 UI 保持不變；若 target 因縮減卡片數量失效，受影響玩家要看到重新選擇提示。

### 遊戲畫面

- 中央以正方形卡片區為主，不論裝置都同時顯示全部卡片。
- 畫面持續顯示目前回合、自己目標、雙方連線狀態與本回合已採取的行動。
- 自己的秘密目標預設以小型固定按鈕或摘要顯示，點擊後才開啟唯讀放大視窗；不能長期占用卡片區空間。
- 蓋牌應像實體桌遊翻下卡片，仍保留編號、姓名或「已蓋牌」文字，且可再次翻回。
- 猜測是高風險操作，按鈕與二次確認視窗需和一般蓋牌明顯區分。
- 斷線暫停時顯示剩餘寬限時間，並停用所有遊戲操作。

## 圖片選擇、裁切與顯示

- 只有房主且房間為 `lobby` 時顯示上傳、替換與名稱編輯 UI。
- 選檔後先在瀏覽器顯示固定正方形裁切預覽，再壓縮為 JPEG 上傳 Firebase Storage。
- 裁切互動使用 react-easy-crop，支援滑鼠／單指拖曳、雙指捏合、滾輪與縮放滑桿，另提供重設位置。只移動、縮放圖片，輸出的裁切框固定為正方形。
- 裁切編輯區是遊戲圖片禁止手勢縮放的例外：手勢僅影響裁切取景，不能縮放整個頁面；棋盤及一般卡片放大視窗仍維持固定尺寸。
- 裁切視窗在手機使用接近全螢幕的 bottom sheet，在平板與桌機使用置中 dialog；確認與取消按鈕不可被軟鍵盤或安全區域遮住。
- 前端要在上傳前檢查檔案類型與大小並顯示可理解錯誤，但 Server 與 Storage Rules 仍須再次驗證。
- Firestore／Server 狀態只提供 `imagePath` 時，前端再依路徑取得下載網址；載入中顯示固定比例 skeleton，失敗顯示同尺寸錯誤卡，避免 grid 跳動。
- 替換圖片成功前保留舊圖；上傳或 acknowledgment 失敗時顯示重試，不得讓卡片變成永久空白。

## Tailwind CSS 規則

- 一般排版、間距、RWD、狀態與互動樣式使用 Tailwind utility classes。
- `globals.css` 只保留設計 token、字型、grain、共用 base style、觸控限制與 Tailwind 無法清楚表達的少量效果。
- 不同狀態的 class 使用完整、可掃描的字串，不動態拼接 Tailwind class 名稱。
- 不混用 CSS Modules、styled-components 或額外 UI component library。

## 無障礙與操作品質

- 卡片以原生 `<button>` 或具等效鍵盤語意的控制實作，不能只綁定 `<div onClick>`。
- 每個一般互動目標至少 `44×44px`；`5×5` 小卡片本身受棋盤空間限制時，整張卡片都是點擊目標，操作按鈕移至放大視窗並維持至少 `44px` 高。
- 所有互動元件保留清楚的 `focus-visible`，並可用鍵盤完成。
- 圖片替代文字至少包含編號與角色名稱；裝飾性紋理使用 CSS 背景或空替代文字。
- 狀態不能只靠色彩表達；蓋牌、目前目標、離線、目前回合皆要有文字或圖示。
- 使用 `aria-live="polite"` 宣告回合、連線與一般錯誤變化；猜中、猜錯或斷線判負等重要結果使用更明確的 dialog 或 `assertive` 訊息。
- 支援 `prefers-reduced-motion`；關閉翻牌動畫後仍須看得懂狀態。
- 不讓 grain、陰影、動畫或自訂字型阻擋首要操作。

## 錯誤、載入與重連

- 初次載入房間時顯示固定版面 skeleton，不先渲染可操作的假資料。
- Socket 未連線或正在重連時顯示明確狀態，停用會改變資料的操作。
- acknowledgment 錯誤以貼近操作位置的文字顯示；未知錯誤再使用頁面級提示。
- 收到新的 `room:state` 時，如果目前放大的卡片已不存在，立即關閉 modal 並告知卡組已更新。
- 重新連線後，以 Server 狀態復原目前回合、目標與 `foldedCardIds`，不得沿用舊 React state 猜測結果。

## 前端驗收標準

至少檢查下列 viewport：`320×568`、`390×844`、`768×1024`、`1024×768`、`1440×900`，並檢查平板旋轉前後。

- 首頁一眼能分辨創建與加入房間。
- 房主與來賓能一眼辨識自己目前可執行的操作。
- `9／16／25` 張卡片在手機、平板與桌機都完整位於同一個中央正方形內，分別維持 `3×3／4×4／5×5`，且沒有水平捲動。
- 雙方不論裝置尺寸都依 `cardId` 顯示相同順序；`25 → 9` 後只留下前九張且不重排。
- 點任何卡片都能在畫面中央看到固定大小的放大圖片，底部操作依 `lobby／playing／paused`、回合與蓋牌狀態正確切換。
- 放大圖片不能被拖曳、捏合或雙擊改變大小；正式遊戲畫面不因誤觸產生頁面位移或縮放。
- 指認必須二次確認；蓋牌與翻回要在 Server acknowledgment 後更新，重新整理與重連後仍一致。
- 軟鍵盤、手機網址列、瀏海、動態島與底部系統手勢區不遮住主要操作。
- 鍵盤可完成開啟卡片、操作、關閉 modal，且焦點順序正確。
- Retro Design 在關閉 grain、動畫與自訂字型後仍然成立。
- 色彩或圖片載入失效時，遊戲資訊與操作仍保持可讀、可用。
